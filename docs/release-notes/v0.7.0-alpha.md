# NEXUS PRIME v0.7.0-alpha

**Estado: versión de trabajo en preparación para validación.** Estas notas describen el árbol de trabajo, incluidos cambios locales pendientes de publicación; no confirman un tag, release ni despliegue de esta revisión.

NEXUS PRIME es una Digital Twin Platform para representar infraestructura, aplicaciones y laboratorios de ingeniería desde distintas perspectivas operacionales.

## Workspace Engine

- **Operations Center:** experiencia operacional existente con grafo mixto de fuentes reales y simuladas.
- **Security Command:** visualización de amenazas, incidentes y métricas simuladas; acciones deshabilitadas.
- **Digital Twin:** mapa de infraestructura y salud simulados, independiente del descubrimiento LIVE.
- **AI Operations:** Knowledge Core e interfaz con contenido predefinido, sin proveedor de IA conectado.
- **Executive Overview:** indicadores ilustrativos orientados a gestión.
- **Homelab Mission Control:** flota, almacenamiento, respaldos y salud de ejemplo.

La selección persiste en el navegador; las escenas 3D se cargan bajo demanda y tienen alternativas para movimiento reducido o ausencia de WebGL.

## Infrastructure Sources

| Fuente | Estado comunicado | Alcance |
|---|---|---|
| Docker LIVE | **VALIDATED** | Inventario y estadísticas del Engine mediante Docker Socket Proxy; fallback simulado. |
| Coolify LIVE | **VALIDATED** | Descubrimiento de proyectos, entornos, recursos y despliegues activos. |
| Proxmox LIVE | **VALIDATION IN PROGRESS** | Adaptador implementado; autenticación, permisos e inventario pendientes de validación. |

Operations Center clasifica nodos como LIVE, SIMULATED, OFFLINE o UNKNOWN, permite filtrar por procedencia y sustituye nodos simulados únicamente cuando existe una identidad explícita equivalente. System Diagnostics resume fuentes y Mission Console identifica la procedencia de los eventos. Las simulaciones se conservan.

## Operational Validation

Los estados de Docker y Coolify son resultados reportados por el usuario para VPS-WEB, no comprobaciones repetidas desde este entorno. Para Proxmox, se reportó resolución de `proxmox.unab.ccp` y una respuesta HTTPS 401 sin token: DNS, CA y nombre de certificado quedaron validados, pero el 401 no valida credenciales ni permisos. El Compose mantiene `NODE_EXTRA_CA_CERTS` y TLS estricto.

## Limitaciones y próximos pasos

- Publicar la revisión candidata y ejecutar build, lint, tests y la [Deployment Validation Checklist](../deployment-coolify.md#deployment-validation-checklist) sobre esa revisión.
- Verificar autenticación, permisos, health e inventario Proxmox LIVE sin revelar el token.
- No atribuir a producción los cambios locales hasta desplegarlos y comprobarlos.
- La API no implementa autenticación propia; proteger el acceso mediante una capa externa y mantener API y Docker Socket Proxy internos.
- No hay integración de IA ni de herramientas SOC; los indicadores de los workspaces simulados no representan telemetría real.

La versión no está certificada como `DEPLOYMENT READY`.
